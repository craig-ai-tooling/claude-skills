# docs.spectrocloud.com — site map and lookup path

Public Palette documentation, built on Docusaurus, served at `docs.spectrocloud.com`.
It is the **only** source you may link in anything customer-facing — never a Slite,
Confluence, or Google Drive URL. Read `super` first if the question is about
product/positioning/pricing rather than "what does the public page say" — Super
already indexes this site and most other lookups belong there.

## Decide which tool first

| Need | Use |
|---|---|
| Synthesized answer, don't care which doc it came from | `super-axi ask` — already indexes this site, see `super` |
| The public URL to cite for a claim you already believe | Section map below, then confirm the page exists |
| Exact current wording of a specific page | `curl` or WebFetch the URL directly |
| "Which page covers X" and you don't know the URL | WebSearch with `site:docs.spectrocloud.com`, or grep a fresh sitemap pull |
| Spot-checking a draft's public-doc citations before it ships | Fetch each cited URL and confirm it says what the draft claims |

There is no sanctioned scraping tool to build here: the site has no public search
API (its widget is Kapa, `POST api.kapa.ai/query/v1/projects/<id>/chat/`, and it
401s without a credential we don't have) and a `docs-mcp` server exists
(`https://spectro-cloud.mcp.kapa.ai`, Google/GitHub login) but the house preference
is CLI over MCP and curl already does everything the read path needs. This is a
reference, not a tool.

To regenerate this table (site adds/reshuffles pages between checks):
```bash
curl -s https://docs.spectrocloud.com/sitemap.xml -o /tmp/sitemap.xml
grep -o "<loc>https://docs.spectrocloud.com/[^<]*" /tmp/sitemap.xml \
  | sed 's#<loc>https://docs.spectrocloud.com/##' | cut -d/ -f1 | sort | uniq -c | sort -rn
```

## Versioning

The site is versioned per Palette release (`v3.4` through `v4.10` seen 9/24/26) plus
an unversioned "current" tree that tracks the latest release. **Default to the
unversioned URL** (e.g. `/clusters/edge/`) unless the customer is pinned to an older
Palette version — then use the versioned path (`/v4.5/clusters/edge/`). A versioned
page can differ meaningfully from current; don't assume they match.

## Authoritative vs. lagging — how to tell which

- **Autogenerated sections are authoritative and current**: `/api/` (built from the
  API spec) and `/integrations/packs/` (built from the pack registry) reflect what's
  actually shipped, same-day. Trust these over Super for exact field names, endpoint
  paths, and pack version numbers.
- **Hand-authored conceptual/how-to pages lag internal knowledge**, per `super`:
  Super's own corpus (Slite + Slack + Drive + this site) is "often weeks" ahead on
  anything newly shipped, positioning, or roadmap. If a doc page and Super disagree
  on a recent feature, Super is more likely current — but confirm with a person or a
  changelog before asserting it externally, since Super is retrieval+synthesis, not
  the source of truth itself.
- **Never expect this site to carry**: pricing, roadmap, competitive positioning, or
  demo scripts. Those live in Super/Slite only and must never leak into a
  customer-facing doc link or quote.
- **Release notes** (`/release-notes/`, 4 pages seen) are the fastest way to check
  whether a specific capability has shipped publicly yet, before citing a doc page
  that describes it.

## Fetching without an API key

No auth needed — this is a public docs site. `robots.txt` disallows a named list of
AI-training crawlers (`ClaudeBot`, `anthropic-ai`, etc.) from the whole site, but that
is advisory for crawlers claiming those user-agents; it does not block normal HTTP
requests, and both `curl` and the WebFetch tool retrieve pages fine (verified 9/24/26).
`/search/`, `/tags/`, `/apis/`, and a few other paths are excluded from the sitemap by
`robots.txt` but still resolve if you already have the URL.

```bash
curl -s https://docs.spectrocloud.com/clusters/edge/ | pandoc -f html -t plain   # quick text dump
```
or hand the URL to WebFetch with a specific extraction prompt when you need a
synthesized answer instead of raw HTML.

## Citing a doc page in a customer-facing deliverable

1. Get the answer from Super or your own knowledge first.
2. Find the matching public URL (site map above, or WebSearch
   `site:docs.spectrocloud.com <topic>`).
3. **Open the URL and confirm it actually supports the claim** before it ships —
   pages get restructured; a URL that used to cover something can redirect or split.
4. Link the unversioned URL unless the customer's Palette version is pinned and older
   than current (see Versioning above).
5. Keep any internal-only detail (pricing, roadmap, competitive framing, SE-only
   config) out of the same paragraph — it has no public page to point to and should
   not appear in customer-facing text at all, per `super` and the house pricing
   rule (`OPP.md` / prep doc only).

## Failure modes

| Symptom | Cause / fix |
|---|---|
| `sitemap.xml` 404s or is empty | Site restructure — check `docs.spectrocloud.com/robots.txt` for the current `Sitemap:` line |
| A cited URL 404s | Docusaurus reshuffled the path; search `site:docs.spectrocloud.com` for the new location before assuming the content was removed |
| Kapa API call 401s | Expected — no public key exists for it; use `docs-mcp` (Google/GitHub login) or curl the page directly instead |
| Doc page contradicts Super | Doc page may be stale on a fast-moving feature, or Super's synthesis may be wrong — check a release note or a person before shipping either claim externally |
